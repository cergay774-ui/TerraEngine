# Terra Shader — оптимизированный шейдер-пак для Minecraft Bedrock (RenderDragon)

Шейдер на основе открытого **Newb X Legacy** ([devendrn/newb-x-mcbe](https://github.com/devendrn/newb-x-mcbe),
v16.56, коммит `c57aefa`, MIT). Материалы `.material.bin` собираются через **Lazurite**.
Главные платформы — Android (основная) и Windows. Приоритет — стабильность и скорость
на слабых телефонах: все тяжёлые эффекты выключаются пресетами, а «Картошка» по стоимости
не дороже оригинального Newb X.

| | |
|---|---|
| Целевая версия игры | Minecraft Bedrock **26.52** (Android: `1.26.52.3`), `min_engine_version` 1.26.50 |
| База шейдера | Newb X Legacy 16.56 (ветка `main`, «Update for 1.26.50+») |
| Компилятор | Lazurite **0.10.0** + shaderc из релиза `newb-shader/dev` |
| Исходные материалы | `src-materials-1.26.51.zip` (формат после изменений 26.10/26.30) |
| Android | MB Loader |
| Windows | BetterRenderDragon или Wyvern |

В проекте два пака:
- **Terra Shader** — шейдер для обычного режима графики (работает через MB Loader / BetterRenderDragon,
  в том числе на слабых телефонах);
- **Terra Vibrant** — настройки для официального режима **Vibrant Visuals**: там игра сама рисует
  настоящие отражения блоков и мобов в воде и настоящие тени, а пак добавляет волны, палитры
  рассвета/заката, тёплые факелы и цветокоррекцию Ада/Энда. Загрузчик не нужен
  (см. раздел [Terra Vibrant](#terra-vibrant-vibrant-visuals)).

---

## Быстрый старт

```bash
cd terra-shader
python -m pip install -r requirements.txt   # Python 3.11+
./build.sh                                   # Windows: build.bat
```

Первый запуск сам скачает shaderc и исходные материалы (`build setup`), затем соберёт
все 7 пресетов и упакует `build/terra-shader-1.0.0-android.mcpack`
(на Windows — ещё и `...-windows.mcpack`), а также `build/terra-vibrant-1.0.0.mcpack`.
Импорт: открыть `.mcpack` → игра импортирует пак.

### Как добавить/изменить пресет

Все параметры качества — только в `presets.toml`. Секция `[defaults]` содержит полный
список параметров, пресет перечисляет только отличия:

```toml
[[preset]]
id = "my_phone"
name = "Мой телефон"
memory_tier = 0
[preset.params]
water_waves = 3
puddles = true
ao = 0.3
```

Ключ превращается в define `TS_<КЛЮЧ>`: `true/false → 1/0`, целые — как есть, дробные
сохраняют точку и дополнительно дают `TS_<КЛЮЧ>_ON`. Опечатка в ключе или неверный тип —
ошибка сборки. Цвета и интенсивности (общие для всех пресетов) — в `src/newb/config.h`.

## Сборка

```bash
./build.sh                         # всё: setup при необходимости + все пресеты + Terra Vibrant
./build.sh vibrant                 # только Terra Vibrant (секунды, любая ОС)
./build.sh pack -p android         # только Android (ESSL)
./build.sh pack -p android windows # оба (windows — только на Windows)
./build.sh pack --no-zip           # без архива, папка build/pack-<профиль>/
./build.sh pack -v 3               # версия 1.0.3
./build.sh mats -s high -m RenderChunk   # быстро собрать один материал одного пресета → build/<профиль>/<пресет>/
./build.sh manifest                # обновить manifest.json из presets.toml
./build.sh setup --reset           # перекачать тулчейн
```

Что делает `pack`:
1. копирует `src/common` (material.json + uniforms) в каждый материал;
2. компилирует все 13 материалов для каждого пресета с его define'ами;
3. пресет `default_preset` кладёт в корень `renderer/materials/`;
4. в `subpacks/<id>/renderer/materials/` оставляет только материалы, **отличающиеся** от корня
   (распакованный пак ~28 МБ вместо ~95, `.mcpack` ~2.9 МБ);
5. генерирует `manifest.json` (сабпаки в порядке `presets.toml`), `COPYRIGHT.txt`, `PRESETS.txt`;
6. архивирует в `build/terra-shader-<версия>-<профиль>.mcpack`.

Скомпилированные материалы кэшируются в `build/cache` по хэшу исходников + define'ов:
полная сборка Android ≈ 4 мин, повторная без изменений ≈ 1 с, после правки одного пресета
пересобирается только он.

Если в `PATH` есть `glslang` (пакет `glslang-tools`), Lazurite дополнительно проверяет
каждый сгенерированный ESSL-шейдер.

**Windows-материалы (Direct3D) компилируются только на Windows** (ограничение shaderc).
Без Windows-машины используйте GitHub Actions: workflow `.github/workflows/terra-shader.yml`
собирает оба `.mcpack` (Actions → terra-shader → Run workflow → артефакты).

### После обновления игры

RenderDragon меняет формат материалов в крупных обновлениях (так было в 26.10 и 26.30).
Порядок действий:
1. дождаться обновления Newb X / Lazurite под новую версию;
2. поменять `NS_DEV_MAT_SRC_URL` в `tool/util.py` (новый `src-materials-*.zip`) и версию
   `lazurite` в `requirements.txt`; если upstream менял `.sc`-файлы материалов — перенести
   эти изменения (наши правки локализованы, см. «Изменённые файлы»);
3. `./build.sh` — setup перекачает тулчейн автоматически, кэш инвалидируется сам.

## Установка

### Android (MB Loader)
1. Установить **MB Loader** ([Google Play](https://play.google.com/store/apps/details?id=io.github.bambosan.mbloader)).
2. Запускать Minecraft **через MB Loader** (он внедряет загрузку пользовательских материалов).
3. Открыть `terra-shader-1.0.0-android.mcpack` (через файловый менеджер «Открыть с помощью → Minecraft»).
4. Настройки → Глобальные ресурсы → активировать **Terra Shader**.
5. Нажать ⚙ у пака и выбрать пресет. На слабом телефоне начните с «Низкие» или «Картошка».
6. Перезайти в мир после смены пресета.

### Windows (BetterRenderDragon / Wyvern)
1. Установить **BetterRenderDragon** и включить в его настройках загрузку материалов из
   ресурспаков. Если ваша сборка BRD не поддерживает 26.5x — используйте **Wyvern**
   ([релизы](https://github.com/mcbegamerxx954/wyvern_releases/releases/latest)); upstream Newb X
   сейчас рекомендует именно его: запустить игру → «Inject» в Wyvern.
2. Импортировать `terra-shader-1.0.0-windows.mcpack` двойным кликом.
3. Глобальные ресурсы → активировать Terra Shader → ⚙ → пресет.

Без загрузчика пак ничего не меняет: обычный клиент игнорирует пользовательские материалы.
При первой активации игра может выбрать крайний правый пресет — проверьте ползунок.

## Как это устроено

### Стабильность анимации (`functions/time.h`)
- **Таймер.** Вся анимация берёт время из `ViewPositionAndTime.w` — игрового таймера рендера в
  секундах, не счётчика кадров, поэтому скорость не зависит от FPS.
- **Зацикливание.** Время оборачивается `mod(t, 1800 с)` в `highp` до любых вычислений.
  Каждая частота анимации округляется до целого числа циклов за период (`NL_SNAP_W`,
  `NL_SNAP_F`), прокрутки — `nlScroll()`. Поэтому в момент оборота все синусы имеют то же
  значение — шва нет, а аргументы `sin()` остаются маленькими: нет рывков и «ускорения» волн
  после многих часов игры (особенно на мобильных GPU с fp16).
- **Мировые координаты.** Для вершин чанка `a_position` задана относительно начала рендер-чанка;
  начало чанка — целое число, поэтому оно округляется (ошибка float исчезает), оборачивается по
  модулю 512 блоков и к нему прибавляется точная локальная позиция. Все узоры (волны, шум, лужи,
  каустика, лава) строго периодичны с периодом 512 (`NL_SNAP_K`, `nlNoiseP`), поэтому оборот
  координат не виден, а эффекты привязаны к миру и не «едут» за игроком.

### Вода (`functions/water.h`)
- До 6 направленных слоёв волн от зыби 12 блоков до ряби 1.45 блока; высота — синусы, нормаль —
  формулы Gerstner (острые гребни). Направления — целые векторы на периоде 512, скорость — по
  дисперсии глубокой воды, округлённая до целых циклов.
- Крупномасштабный шум (32 блока) меняет амплитуду длинных и коротких волн отдельно (штиль и
  рябь в разных местах) и искривляет фронты волн — повторяющегося узора не видно.
- Короткие волны затухают с расстоянием, вдали шероховатость растёт — нет мерцания.
- Вершины поверхности опускаются по волнам (никогда не выше исходной поверхности).
- Цвет: «толщина» воды вдоль луча зрения (угол + расстояние) смешивает мелкую бирюзовую и
  глубокую синюю палитры с цветом воды биома; сверху прозрачно, под углом и вдали — насыщенно.
- Френель Шлика с учётом roughness; отражение процедурного неба с солнцем/луной, облаками и
  сиянием (опционально), бликовое пятно солнца/луны, свет факелов. Под крышей отражение неба гаснет.
- **Roughness** расширяет блик, снижает контраст облаков и при ≥ 0.55 полностью выключает их
  расчёт — «размытые отражения» дешевле.
- Под водой: каустика (повершинно или попиксельно), синий туман игры с подкраской Newb,
  лёгкое покачивание изображения; поверхность снизу — «окно Снеллиуса».

### Лужи (`functions/rain.h`)
- Дождь определяется по параметрам тумана (как в Newb X); в Аду, Энде и под водой — 0.
- Только горизонтальные грани (нормаль из производных позиции на экране) и только при
  максимальном skylight — под крышей сухо.
- Форма — «поле высот» из мирового шума трёх масштабов + региональный член. Лужа — часть поля
  выше «уровня воды», который растёт с силой дождя. У каждого локального максимума своя
  высота, поэтому лужи появляются по одной (симуляция: 7 → 22 → 144 → 830 луж на 512×512 по мере
  усиления дождя, при полном дожде ≈19% открытой земли) и так же по одной высыхают, сжимаясь от
  краёв, пока игра плавно снижает дождь.
- Внутри — отражение неба (Френель) с кругами от капель (2 слоя ячеек, частота капель зависит от
  дождя), по краям — потемневший мокрый ободок, все открытые грани слегка темнеют.
- Освещение: отражение умножается на skylight, добавляется отражённый свет факелов, ночью
  отражается тёмное небо; собственного свечения нет.

### Свет и тени (`lighting.h`, `RenderChunk/fragment.sc`)
- Тёплые факелы, холодная луна, отдельные палитры **рассвета** и **заката** (неба и солнца),
  день и ночь; рассвет/закат различаются по направлению солнца, переключение — в полдень/полночь,
  где их вес равен нулю, поэтому переходы плавные.
- Мягкие тени по skylight-лайтмапе (`NL_SHADOW_SOFTNESS`), облачные тени Newb.
- AO: из цвета вершин выделяется ванильное AO (деление на ванильное затенение грани) и
  усиливается; для блоков с цветом биома (трава, листва) оставлено ванильное.
- Затенение граней по направлению солнца/луны: прямой свет передаётся отдельно (`v_sun`), грани к
  солнцу светлее, от солнца — темнее.
- Свечение: текстуры руд/светокамня/фонарей из Newb X + определение светящихся блоков по
  лайтмапе (яркие текселы на равномерно освещённой грани с максимальным блочным светом — морские
  фонари, грибосвет, жаболампы, лава…), лава с течением UV и пульсацией.
- Настоящих shadow maps нет (недоступны в классическом пайплайне) — только имитация.

### Цветокоррекция Ада и Энда (`functions/grade.h`)
- Биом определяется по `FogColor`, приведённому к хроматичности (не зависит от яркости), и
  сравнивается с ванильными цветами тумана: багровый лес → тёплый красный, искажённый лес →
  бирюзовый, долина душ → холодный голубой, базальтовые дельты → серая дымка, пустоши →
  оранжевый.
- Игра при переходе между биомами линейно смешивает туман, поэтому шейдер ищет пару эталонов,
  на отрезке между которыми лежит текущий туман, и позицию на нём → веса меняются плавно и
  монотонно, без вспышек «третьего» биома (проверено численно для всех 10 пар).
- В Аду коррекция ослабевает с туманом — дальние блоки совпадают с цветом пустоты.
- Энд — отдельная фиолетово-тёмная палитра (террейн, мобы, небо Энда).

## Terra Vibrant (Vibrant Visuals)

**Vibrant Visuals** — официальный графический режим Minecraft (Настройки → Видео → Графический
режим). В нём игра сама рисует **отражения блоков и мобов в воде (SSR)**, настоящие тени,
объёмный свет. Шейдеры для него писать не нужно: Mojang даёт официальные JSON-настройки, и
Terra Vibrant использует только их. Поэтому:
- **MB Loader / BetterRenderDragon не нужны**, пак работает в обычном клиенте;
- пак не ломается при обновлениях так, как `.material.bin`: JSON-форматы версионированы;
- работает только на устройствах, где игра разрешает Vibrant Visuals (нужен достаточно мощный
  GPU — на слабых телефонах пункта может не быть, тогда используйте Terra Shader).

### Что настраивает
| Что | Файл | Описание |
|---|---|---|
| Волны и цвет воды | `vibrant.toml` → `water/*.json` | волны включены (в ванили выключены), чистая голубая вода, мутная зелёно-бурая в болотах, каустика, примесь цвета воды биома |
| Пресеты волн (сабпаки) | `vibrant.toml` `[[preset]]` | «Без волн (быстрее)», «Спокойная вода» (8 октав), «Обычные волны» (16), «Штормовые волны» (28) |
| Солнце и луна | `pack/lighting/terra_default_lighting.json` | отдельные цвета солнца на рассвете (розово-золотой) и закате (глубокий оранжевый), холодная луна, голубоватый ночной ambient |
| Небо | `pack/atmospherics/terra_default_atmospherics.json` | горизонт: тёплый оранжевый закат, розово-фиолетовый рассвет |
| Факелы | `pack/local_lighting/local_lighting.json` | тёплый свет факелов и фонарей |
| Цветокоррекция | `pack/color_grading/*.json` | мир: чуть насыщеннее, холодные тени и тёплые света; Ад: пустоши — оранжевый, багровый лес — красный, искажённый — бирюзовый, долина душ — холодный голубой, базальтовые дельты — серая дымка; Энд — фиолетово-тёмная |
| Тени | `pack/shadows/global.json` | мягкие тени |

Переходы между биомами **игра делает сама**: освещение, атмосфера и цветокоррекция плавно
смешиваются по мере движения игрока, вода — по каждому блоку воды.

### Как устроен
Ванильные настройки конкретных биомов приоритетнее глобальных файлов пака, поэтому сборщик
скачивает ванильные `biomes/*.client_biome.json` для тега `samples_tag`
(репозиторий [Mojang/bedrock-samples](https://github.com/Mojang/bedrock-samples), сейчас `v1.26.50.4`)
и меняет в них только идентификаторы из `[biomes.replace]` / `[biomes.set]`; всё остальное
(звуки, туман, цвета травы) остаётся ванильным. Особые ванильные настройки пустыни, болот,
мезы и т.п. сохраняются. Перед упаковкой проверяется: все используемые `terra:*`-идентификаторы
определены, значения в документированных диапазонах, один оператор тонмаппинга.

После обновления игры: поменять `samples_tag` на новый тег bedrock-samples и пересобрать.

### Установка
1. Убедиться, что в Настройки → Видео есть **Vibrant Visuals**, и включить его.
2. Открыть `terra-vibrant-1.0.0.mcpack` → импорт.
3. Глобальные ресурсы → активировать **Terra Vibrant** → ⚙ → пресет волн.
4. Запускать игру можно обычной иконкой. Если вы ставили и Terra Shader: для Vibrant Visuals
   запускайте игру **без** MB Loader (или выключите Terra Shader), чтобы подменённые материалы
   обычного режима не мешали. Оба пака можно держать активными (туман Энда у них общий), но
   **Terra Vibrant должен стоять выше Terra Shader** в списке глобальных ресурсов: оба пака
   содержат файл биома Энда, и в Vibrant Visuals нужен вариант из Terra Vibrant.

### Ограничения Terra Vibrant
- SSR — это возможности игры: не отражается то, чего нет на экране; стекло SSR не получает.
- Волны в Vibrant Visuals — эффект изображения, геометрия воды не двигается.
- Луж под дождём, течения лавы и т.п. из Terra Shader здесь нет — в Vibrant Visuals нельзя
  подменять шейдеры через JSON.
- Значения подобраны по документации и ванильным файлам, в игре не проверены — палитры и волны
  может понадобиться подстроить в `vibrant/`.

## Известные ограничения

- **Нет настоящих теней** — shadow maps недоступны в классическом пайплайне RenderDragon;
  тени имитируются через skylight-лайтмапу, AO и затенение граней.
- **Нет отражений блоков и мобов** — вода и лужи отражают только процедурное небо, солнце, луну,
  облака и сияние (SSR невозможен без буфера глубины/цвета). Настоящие отражения есть в режиме
  Vibrant Visuals — для него пак Terra Vibrant.
- **Лужи держатся недолго после дождя** — у шейдера нет памяти между кадрами, лужи следуют за
  интенсивностью дождя, которую игра снижает за несколько секунд.
- Лужи появляются и при снегопаде (тип осадков по туману не различить); и на любых
  горизонтальных гранях под открытым небом (полублоки, ковры и т.п.).
- Глубина воды неизвестна (буфер глубины недоступен прозрачной геометрии): «у берега
  прозрачнее» — приближение по углу зрения и расстоянию.
- Свечение по лайтмапе приблизительное: светлые блоки вплотную к источнику света 15 уровня тоже
  слегка светятся.
- Цветокоррекция Ада рассчитана на ванильные цвета тумана; ресурспак, меняющий туман Ада,
  требует обновить `NL_REF_*` в `config.h`.
- Течение лавы и пульсация — только на поверхности стоячей лавы (детектор Newb X); течение UV
  предполагает атлас шириной 64 текстуры, как и glow-эффекты Newb X.
- Затенение граней предполагает ванильные коэффициенты (верх 1.0, низ 0.5, Z 0.8, X 0.6).
- Небо и облака используют незацикленное время (в `highp`), чтобы облака в отражениях совпадали
  с небом; на них зацикливание не распространяется.
- После крупных обновлений игры материалы, скорее всего, придётся пересобрать (см. выше).
